# 挙上log

筋トレと体重の記録を、サーバーなしで完結させる個人用アプリ。
**https://avocadoisi.github.io/open-workout-memo/**

## コンセプト

「開いて、書いて、閉じる」。アカウントもサーバーも同期もない。
データはブラウザの IndexedDB に置き、静的サイトとして配信する。所有はエクスポートで担保する。

- 記録は 1 セット = 1 レコード（日付 / 種目 / 重量 kg か「自重」 / 回数 / メモ / 保存時刻）
- 記録の並びは既定で入力した順（設定で新しい順にもできる）。同じ種目が連続する範囲だけをまとめる（ベンチ→スクワット→ベンチ は 3 グループ）。グループ見出しの↑↓で並べ替えられ、各セットの↑↓で同じグループ内を並べ替えられ、手動で並べ替えた順は `order` に保存する
- 重量と 1RM は整数部3桁・小数1桁で右揃え（5 は 5.0、ゼロ埋めはしない）。kg と「（参考値）」は数値の外に置き、記録・履歴・保存画像で同じ見た目にする
- 推定 1RM は O'Conner `weight * (1 + reps / 40)`。1 回は挙上重量を小数1桁に丸めた値、15 回超は参考値と注記
- 重量は「自重」も選べる（重量は 0 として保存）。記録日から1ヶ月以内（記録日以前の直近30日）に体重の計測があれば、最新値をメモの先頭に「体重 72.5kg」と書く。メモは注記込みで30文字、編集で保存し直しても注記は重複しない。1RM は体重が分かるときだけ参考値で出し、ボリュームとグラフも体重で換算する（体重不明の自重は 1RM を出さず、ボリュームは 0）
- 種目・部位は UI から追加。種目の名前と部位はデータ画面の鉛筆から変えられる。削除はアーカイブ（過去の記録は残す）
- データ画面の種目一覧は部位（腕・肩・背中・胸・脚、他は末尾）→ 名前の順で並べる
- 種目のセレクト（記録・グラフ・履歴）は、トレーニングした日数が多い順（同じ日に何セットあっても1日）。日数が同じなら最終実施日が新しい順、次に名前順。まだ記録の無い種目は名前順で後ろ。部位で絞っても同じ順で、部位の並びは腕・肩・背中・胸・脚（ほかは末尾）の固定
- 記録の種目は、グループの見出しのセレクトからまとめて、各行の鉛筆から1セットずつ変えられる（アーカイブ済みでも、いま付いている種目は選べる）。見出しのセレクトが種目名表示を兼ねる
- 記録フォームの種目の既定は、前回選んだ（または記録した）種目。まだ無ければ記録した日がもっとも多い種目（同じ日に複数セットあっても1日。部位を絞ればその部位の中で）。編集で開いたときはそのセットの種目のまま
- セットの複製（コピーボタン）は重量・回数・メモを引き継ぎ、コピー元の直後にやったものとして並ぶ（同じ種目のグループが分かれない）
- グループ見出しには 1RM とボリュームを出す。1RM とボリュームは同じ行に置き、幅が足りない画面では名前の次の行にまとめて折り返す
- メモは重量・回数と列を揃える（数値の左端に合わせる）
- 保存画像ボタンは「記録」見出しの右
- 体重などの指標は筋トレと別トラック（単位は重さ / 長さ）。保存は kg / cm 固定
- エクスポートは JSON と画像。インポートはファイルかクリップボードから読み、マージか全置換で復元する
- 演出より速度。画面切替や配色変更のフェードはしない。動きは操作の手応え（押した・保存できた）にだけ使い、待たせない
- やらないこと: ログイン、複数端末同期、サーバー処理、SNS 連携

## 画面

ホーム（`#/`）にプレビュー付きのタイルが並び、押すと全画面で開く。開いた画面のヘッダーには「最小化」があり、ホームに戻る。記録（`#/record`）/ 履歴（`#/history`、カレンダー・種目ごと・部位ごと。カレンダーの週の始まりは設定で日曜 / 月曜を選べる。種目ごとは部位で種目を絞り込める）/ グラフ（`#/chart`、1RM とボリュームの推移。種目は部位で絞り込め、アーカイブした種目も選べる。種目の既定は記録した日がもっとも多い種目（部位を変えたときも同じ）で、前回見ていた部位と種目は端末に覚えておき、開き直すとその組み合わせに戻る。タップで拡大し、ピンチ / ホイールで時間軸を伸縮）/ データ（`#/data`、エクスポート / インポート（ファイル・クリップボード）/ 全削除）/ コンセプト（`#/about`、タイトル横の「?」）/ 設定（`#/settings`、ヘッダーの歯車。配色・タイトル・記録の並び・カレンダーの週の始まり）。この2つはタイルには並べない。

## データモデル

```js
exercise:   { id, name, bodyPart, archived }        // 初期は Big3
workoutSet: { id, date, exerciseId, weight, reps, memo, createdAt, order?, bodyweight?, bodyweightKg? }
            // date は 'YYYY-MM-DD'、weight は kg（自重は 0）、createdAt は保存時刻（Date.now()）
            // order は手動の並び（無ければ createdAt、コピーした行はコピー元の直後）、bodyweight は自重、bodyweightKg は記録日までの直近30日の体重（メモ・1RM・ボリューム用）
metricDef:  { id, name, unit: 'weight' | 'length' }
metricLog:  { id, date, metricDefId, value }
// export/import: { schemaVersion: 1, exportedAt, exercises, workoutSets, metricDefs, metricLogs }
```

インポートはマージ（確認なし）と全置換（確認あり）の2つ。マージは id が同じ行を上書きし、id が違っても「日付・種目・重量・回数・メモ」が同じセットは既存とインポートの件数の多い方に揃える（同じファイルを何度入れても増えず、同日 80kg×5 の3セットは3セットのまま、インポートが4セットなら1セットだけ足す）。メモは体重の自動注記を外して比べる。種目は名前、指標は名前＋単位が同じなら手元の id に読み替えて同名を増やさない。マージ結果は「追加 / 更新 / 据え置き」の件数で出す。未知の `schemaVersion` はどちらも拒否。
`createdAt` を持たない古い記録は 0 として扱う。古い順では読み込んだ順（`getAll` の順）で先頭に、新しい順ではその逆順で末尾に並ぶ。

big3-tracker の計画画面からコピーした JSON も、「クリップボードからインポート」で同じ確認に進める。種目名が同じなら手元の種目に寄せ、セットは計画上の日付で入る（同じ計画を何度取り込んでも増えない）。

## 構成

Vanilla JS、ビルドなし、npm 依存なし（画像化の html2canvas、グラフの Chart.js、見出しフォントの Dela Gothic One だけ CDN から読む）。
`index.html` / `app.js`（ハッシュルーティング）/ `dom.js` / `db.js` / `merge.js`（インポートの読み込み検証とマージ規則）/ `prefs.js` / `training.js` / `views/*.js`（各画面）/ `styles.css`。
各 view は `export const view = { id, label, mount(container) }` を出す。
配色はヘッダーの丸3つで切り替える（gruvbox light / catppuccin latte / tokyonight night）。色は `styles.css` の `--gb-*` にだけ書き、画面側は参照する。

`manifest.json` / `sw.js` で PWA にしてある。一度開けば機内モードでも記録・履歴・グラフが開く。シェル（HTML / JS / CSS / 画像）は版数付きキャッシュに一式まとめて install し、全ファイルが揃ってから切り替えるので、更新途中の新旧混在は起きない。シェルを変更したら `sw.js` の `CACHE` を上げる（上げないと配信中の版は切り替わらない）。CDN は別キャッシュでキャッシュ優先。

## テストデータ

「データ → インポート」で読むと、記録の入った状態を試せる。

- `sample/test-data.json` — 3ヶ月・週2回・300セット（体重・ウエストも）
- `sample/test-data-3years.json` — 3年・週2回・3,630セット（体重 192件）。動作の重さを見るとき用

インポートはマージなので、テストデータは既存の記録に足される。戻すときは先に自分のデータをエクスポートしておき、あとで全置換する。
試したあとはデータ画面の一番下の「全削除」で戻せる（タイトルを入力すると消え、次にページを開き直すと Big3 と体重だけの初期状態になる）。

## 開発

ローカルは `python3 -m http.server 8000` → http://localhost:8000/（`file://` では ESM が動かない）。
テストは `node --test`（`training.test.mjs` / `merge.test.mjs` / `order.test.mjs` / `sw.test.mjs`、依存なし）。
PWA の挙動（オフライン）は https か localhost でしか試せない。

変更は issue → ブランチ → PR → マージ（global の `dev-workflow` skill）。

## デプロイ

マージではデプロイしない。指示があったときだけ `gh workflow run deploy.yml` を実行する
（マージのたびに CI を走らせないため。Pages の Source は「GitHub Actions」）。
シェルを変更したデプロイでは、`sw.js` の `CACHE` を上げてから実行する。
